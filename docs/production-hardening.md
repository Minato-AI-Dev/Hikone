# Production reliability and release checks
- CI、Pages、Vercelはいずれも `scripts/check-release.mjs` を実行します。npm audit（moderate以上）、ユニットテスト、API型チェックを通過しなければ公開ビルドは失敗します。
- テスト用子プロセスには配信環境の秘密値を渡しません。実Redisのテストは明示的に有効にした隔離Previewのみです。
- 2026-10-28の監査で検出されたVitest/mockerとundiciを修正バージョンへ更新し、直接依存を固定します。依存更新後はlockfileをコミットします。
- 履歴は実行時に検証し、直近500件まで保持します。保存できない場合はタブ内のメモリで継続し、閉じると消えることを表示します。
- 推薦表示イベントは候補が1件以上ある場合だけ送信します。変更前の研究集計値は書き換えません。修正前後で指標の定義が異なることを分析時に考慮してください。
- クライアント送信失敗はHTTPエラーを含めて警告します。サーバーは analytics_storage_unavailable / analytics_protection_unavailable / analytics_rate_limit_reached を秘密値・IP・入力本文なしで記録します。VercelのLogsで確認できます。外部の通知サービスは未設定です。ネットワークがAPIへ到達しない場合の件数をサーバー側で復元することはできません。
- 管理レポートは1日分18イベントをMGETで取得します。正しい管理トークンを検証した後に、IPあたり毎分60回・全体毎分300回・UTC日5000回の上限を適用します。認証に失敗したリクエストはRedisへアクセスしません。
- Google経路取得の上限は既定で毎分120区間・UTC日300区間を維持します。1操作の最大17区間から、想定操作数×平均区間数で必要量を見積もってください。HIKONE_ROUTES_MINUTE_BUDGET / HIKONE_ROUTES_DAILY_BUDGETで変更できますが、Google側の予算・割当も照合してください。無断で上限を引き上げません。
- HIKONE_ANALYTICS_END_ATにオフセット付き日時を指定すると、以降の収集は410となりRedisへの加算・レート制限予約をしません。不正値では503です。閲覧は停止しません。今回の1か月調査の終了予定は2026-11-28 00:00（日本時間）です。
- 本番の匿名集計には自動削除期限を設定していません。既存の研究データを勝手に削除しないためです。研究終了後の保存・削除時期は運営で決め、別途実施してください。
