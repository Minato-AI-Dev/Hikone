# 実店舗の営業情報を用いた回遊推薦：MVP実装方針

## 目的
彦根の店舗へ案内する際、営業時間・定休日・臨時休業情報に照らして、休業予定の店を積極的に薦めない。営業を保証するサービスではなく、公開情報に基づいた参考案内を行う。

## データの扱い
- 店舗ID、公式URL、情報源の確認日を `shopOperationalFacts` に保持する。
- Google Place IDは店舗単位で照合・登録する。店名だけの曖昧な照合結果を自動採用しない。
- Places API (New) の営業時間情報はサーバー側で取得する。APIキーをクライアントへ公開しない。
- 取得時刻、出典、通常営業時間、例外営業時間、現在の営業予定を区別する。
- 公式の臨時休業告知とAPIデータに矛盾がある場合は「要確認」とし、無条件で営業と断定しない。
- 不定休、隔週定休、臨時休業の未確認は「営業」とみなさない。
- SNS情報は公開・合法的に取得でき、投稿日時・対象日が確認できる場合のみ補助情報とする。無許可スクレイピングを前提としない。

## 判定ステータス
- `scheduled_open`: 参照した情報源では、想定訪問時刻に営業予定。
- `scheduled_closed`: 参照した情報源では、想定訪問時刻に休業予定。
- `unknown`: 情報不足、取得失敗、矛盾、訪問時刻を判断できない場合。

各判定には確認時刻・出典・注意書きを含める。「現在営業中」と「到着予定時刻に営業予定」を混同しない。

## 推薦の方針
1. 既存の `recommend` は徒歩移動時間を参考値とし、帰着までの余裕を見込む。時間内の完了を保証しない。
2. 店舗を含む候補は、予定訪問時刻の営業時間を判定する。予定訪問時刻は概算であり、閉店間際は保守的に扱う。
3. `scheduled_open` の店舗を優先する。
4. `scheduled_closed` は推薦から除外する。
5. `unknown` は「営業未確認」と明示し、営業予定の店舗と同列に扱わない。
6. 公園・史跡など営業時間を持たない地点に店舗向け判定を適用しない。
7. 店舗の推薦条件は営業時間だけではない。入口座標、訪問可能な公開範囲、体験内容、必要に応じて予約の有無も別途確認する。

## 実装ステップ
1. 既存の SHOP001〜SHOP003 の Google Place ID と公式出典を照合する。
2. サーバー側の営業時間取得機能を作り、取得失敗・レート制限・キャッシュの扱いをテストする。
3. 出典付きの営業予定判定を作る。時刻は Asia/Tokyo を基準にする。
4. 店舗推薦・候補画面へつなげる。
5. 開店前、定休日、閉店間際、臨時休業、取得失敗、不定休をテストする。

## 成功条件
- 休業予定の店舗を無条件に薦めない。
- 「未確認」を「営業中」に変換しない。
- 情報源と確認日時が追跡できる。
- 営業予定も参考情報であり、開店を保証する表現を使わない。
- 外部APIを使えない場合も既存の非店舗ルート機能を壊さない。

## 現時点の制約
本書は実装方針であり、Google Places API の導入、Place ID の登録、実際の当日営業判定はまだ実装していない。
